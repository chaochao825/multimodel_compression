# EXP-002: Wan module-target protocol mismatch audit

- Status: frozen and completed
- Date: 2026-08-09
- Gate: G-002
- Claim: C-002
- Candidate line: L-002
- Lane: explore

## Question

Did `EXP-000` make temporal prediction appear harder by forecasting one whole
Wan block residual, whereas TaylorSeer recomputes the current timestep
conditioning and separately forecasts self-attention, cross-attention, and FFN
module outputs?

## Evidence status and scope

- Evidence tier: bounded diagnostic, not confirmatory evidence for a new method.
- Model and sampler: Wan2.1-T2V-1.3B, F81, 480x832, UniPC 20 steps, CFG 5.
- Identities are frozen before capture: prompt 0 / seed 202608070 and prompt 1 /
  seed 202608071 from the existing pilot prompt set.
- Blocks: 0, 12, and 29; both CFG branches; all 20 denoising steps.
- Persist exactly 16 deterministic sampled token rows for each raw module output,
  its current-gated contribution, the block residual, and the block output.
- The dense model output is never substituted. Sampled rows are an audit proxy
  and cannot support a full-tensor, rollout, quality, or speed claim.

## Frozen methods

On identical sampled rows compare:

1. whole-block residual reuse and activated-step first-order Taylor;
2. raw-module reuse and activated-step first-order Taylor for self-attention,
   cross-attention, and FFN separately;
3. module predictions recomposed with the target step's dense block input and
   current AdaLN gates, matching TaylorSeer's Wan placement semantics;
4. horizons H1 and anchor-reset open-loop H2; no scheduler-time interpolation,
   ridge fitting, threshold search, or target-leaking basis fitting.

For H2, the first skipped step is predicted from the two latest dense anchors;
the second recursively consumes the first predicted module output. Errors use
the sampled dense block output norm. Also report each module's raw and gated
temporal drift to identify the dominant source.

## Fairness and validity guards

- Whole-block and module-target methods use the same identities, calls, rows,
  target steps, anchor convention, and output-relative denominator.
- Target-step gates are recorded from the unchanged dense execution. This tests
  target semantics, not deployability; it is labelled a conditioning oracle.
- The frozen evaluator replays Taylor arithmetic and the three residual additions
  in production `bfloat16` order. FP32 additive recomposition is reported only as
  a numerical floor and cannot be counted as predictor error.
- The capture must verify one SA, one CA, and one FFN observation per selected
  block call, exact call order, shape equality, wrapper restoration, and unchanged
  returned tensors in synthetic tests.
- No held-out selection, module-specific schedule search, or post-outcome method
  changes are allowed.

## Outcome mapping

- Protocol-mismatch support: recomposed module Taylor H2 improves at least 50%
  over whole-block Taylor H2 and reaches aggregate error at most 2% on at least
  two of blocks 0, 12, and 29 for both identities.
- Partial boundary: improvement is at least 50%, but the 2% block condition fails.
- Genuine-dynamics failure: improvement is below 50%, or block 12 remains above
  5% aggregate error.
- Invalid: capture is incomplete, dense parity fails, sampled rows differ across
  targets, or target gates/module outputs are misaligned.

## Decision effect

A positive result only revises the interpretation of `EXP-000`: it would justify
a fresh full-tensor selective-refresh Gate faithful to TaylorSeer placement. It
does not revive `C-000`, prove final video quality, or authorize a kernel. A
negative result closes this protocol-mismatch explanation and focuses the
literature gap on schedule selection, fallback, altered quality criteria, and
learned/basis-changing predictors.

## Resource cap and stop rule

At most two dense F81 captures, one per free H200, and one frozen CPU analysis.
Stop after the registered H1/H2 comparison. Do not run rollout, train a predictor,
or implement an acceleration kernel under this Gate.

One repair retry per identity is allowed only if the capture is classified
invalid before any forecast outcome is produced. The invalid logs and code
identity must be preserved, and the retry must not change methods, identities,
thresholds, or the frozen evaluator.

## Frozen outcome

- Classification: genuine-dynamics-failure.
- Whole-block versus module-recomposed Taylor H2: 14.305% versus 14.018%, a
  2.00% relative improvement.
- Block-12 module-recomposed Taylor H2: 22.114%.
- No block met the 2% condition for both identities.
- The one allowed repair was used after an invalid production-dtype replay and
  before forecast outcome inspection. The valid retry achieved exact BF16 replay
  parity and did not change the registered method or Gate.

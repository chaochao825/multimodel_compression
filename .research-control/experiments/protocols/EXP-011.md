# EXP-011: Bounded high-rank block innovation after a rank-16 tail

## Decision question

Can at most 10% additional hardware-regular exact block atoms repair the
high-rank residual that remains after 25% pooled-Q/K support and an adaptive
rank-16 correction?

## Claim and candidate

- Claim: `C-011`
- Candidate: `L-011`
- Gate: `G-011`
- Lane: explore
- Kind: exploratory

## Frozen scope

- Wan2.1-T2V-1.3B F81, Layer 14, step 9, conditional branch.
- Validation: `s02_p00_seed20260741`; one-shot test:
  `s03_p01_seed20260741`.
- Three deterministic 64-query tiles and twelve heads.
- Base support: current pooled-Q/K proxy, contiguous-64 blocks, 25% density.
- Innovation budgets: 2.5%, 5%, and 10% of all valid key tokens, rounded to an
  exact block count.
- Adaptive correction ranks: 16 and 32; rank 16 is decision-bearing.
- Blockwise FP32 reconstruction tolerance: relative L2 `1e-4`.

## Exact innovation identity

For block numerator `N_b`, partition `Z_b`, full partition `Z`, and base sparse
output `Y_S`, define

```
A_b = (N_b - Y_S Z_b) / Z.
```

The implementation must verify that `sum_{b not in S} A_b` reconstructs
`Y_dense - Y_S` within relative L2 `1e-4`. Selected innovation atoms are added
with coefficient exactly one. No posterior scalar or row-wise coefficient is
allowed.

## Registered selectors

1. `mass_top`: omitted blocks with largest exact partition mass.
2. `atom_energy_top`: omitted blocks with largest `||A_b||_F^2`.
3. `rank_tail_greedy`: at each round, use the current post-rank-16 residual to
   shortlist sixteen atoms by positive Frobenius alignment, evaluate the exact
   post-rank-16 objective for that shortlist, and accept the best strictly
   improving atom. Stop at the largest registered budget or when no atom
   improves the objective.

Validation selects one selector per budget by additive rank-16 aggregate error,
then worst-head error and selector name. Test evaluates all selectors as
diagnostics, but only the validation-selected selector determines the outcome.

## Comparators

- `base_sparse_plus_rank`: no innovation atom.
- `additive_shared_z`: `Y_S + sum A_b`, followed by adaptive rank correction.
- `expanded_renormalized`: recompute sparse attention on `S union I` with the
  same innovation blocks, followed by adaptive rank correction.

The additive/expanded comparison isolates whether exact residual atoms add a
new high-rank correction or merely behave like more ordinary sparse support.

## Endpoints and guards

Record aggregate, worst-record, worst-head, worst-head-tile, sparse/base error,
captured defect energy, block budget, selector overlap, objective trace, exact
identity error, hashes, and elapsed time. All outputs must be finite, budget
caps must be respected, greedy objectives must be monotone non-increasing, and
selected innovation blocks must be disjoint from base support.

## Outcome map

- `pass`: validation-selected additive rank 16 reaches test 0.5% / 1% at an
  innovation budget no greater than 10%.
- `deployment-boundary`: additive rank 16 reaches 1% / 2% but misses 0.5% / 1%.
- `normalization-boundary`: additive rank 16 reaches 1% / 2%, while the same
  blocks under expanded renormalized support do not.
- `rank-boundary`: only additive rank 32 reaches 1% / 2%.
- `null`: additive rank 16 misses 1% / 2% through 10% innovation.
- `adverse`: every selected additive setting is worse than the no-innovation
  base or violates a numerical guard.
- `invalid` and `engineering-failure` retain their standard meanings.

Outcome precedence is invalid, engineering-failure, adverse, pass,
normalization-boundary, deployment-boundary, rank-boundary, then null.

## Budget and stop rule

- Existing captures only; at most one H200-hour.
- One valid execution and one pre-outcome engineering repair.
- No deployable selector, partition estimator, training, rollout, kernel, or
  speed claim.
- Stop on one valid outcome, leakage outside registered oracle access,
  non-finite output, failed identity/budget guard, or budget exhaustion.

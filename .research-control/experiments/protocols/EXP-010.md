# EXP-010: Rank-shaped hardware-regular support oracle

## Decision question

Can a target-exposed union of contiguous 64-token blocks actively shape the
25%-sparse attention defect so its adaptive rank-16 tail reaches strict quality
at a density that retains an arithmetic acceleration path?

## Claim and candidate

- Claim: `C-010`
- Candidate: `L-010`
- Gate: `G-010`
- Lane: explore
- Kind: exploratory

## Frozen scope

- Wan2.1-T2V-1.3B F81, Layer 14, step 9, conditional branch.
- Validation: `s02_p00_seed20260741`; one-shot test:
  `s03_p01_seed20260741`.
- Three deterministic 64-query tiles and twelve heads.
- Key blocks are contiguous width 64 with a validity mask for the final block.
- Densities: 12.5%, 18.75%, and 25%; exact integer budgets are rounded from
  valid token density and remain fixed per head/tile.
- Sparse output uses exact selected logits/V and selected-support normalization.
- Blockwise FP32 numerator/partition reconstruction must match the independently
  reduced dense reference within relative L2 `1e-4`; the first engineering run
  established that the original `2e-5` implementation guard was below ordinary
  reduction-order variation (`2.67e-5`).

## Registered support methods

1. `proxy_qk`: existing pooled-Q/K support, no dense target access.
2. `mass_top`: top blocks by exact unnormalized attention partition mass.
3. `value_influence_top`: top blocks by
   `||N_b - Y_dense Z_b||_F^2`.
4. `tail_swap`: gradient-guided fixed-budget discrete swaps, initialized from
   each of the three methods above.

For each density, validation selects the tail-swap initialization by adaptive
rank-16 aggregate error, then worst-head error and initialization name. Test
evaluates proxy, mass, influence, and only the selected tail-swap initialization.

`tail_swap` uses at most eight rounds. At each round, differentiate normalized
post-rank-16 residual energy with respect to continuous block gates at the
current binary support. Evaluate the Cartesian product of eight selected blocks
with largest removal gradient and sixteen unselected blocks with smallest add
gradient as exact discrete swaps. Accept only the best strictly improving swap;
stop otherwise. No density, candidate count, round count, or initialization may
change after outcomes are read.

## Endpoints

For rank 16 and 32 record aggregate, worst-record, worst-head, and
worst-head-tile output relative L2; sparse-only error; selected block overlap;
swap count; objective trace; density; and hashes. All adaptive SVD values are
target-exposed capacity ceilings.

## Outcome map

- `pass`: selected tail-swap adaptive rank 16 reaches test 0.5% / 1% at density
  at most 18.75%.
- `density-boundary`: the strict 0.5% / 1% gate passes only at 25%.
- `deployment-boundary`: rank 16 reaches 1% / 2% at density at most 18.75% but
  misses 0.5% / 1%.
- `rank-boundary`: rank 32 reaches 1% / 2% at density at most 18.75%, but rank
  16 does not.
- `null`: rank 16 misses 1% / 2% at every density through 25%.
- `adverse`: tail-swap is worse than all three initial supports at every density
  or produces a non-finite output.
- `invalid` and `engineering-failure` retain their standard meanings.

Outcome precedence is invalid, engineering-failure, adverse, pass,
density-boundary, deployment-boundary, rank-boundary, then null.

## Budget and stop rule

- Existing captures only; at most one H200-hour.
- One valid execution and one pre-outcome engineering repair.
- No deployable router, latent optimization, rollout, kernel, or speed claim.
- Stop on one valid outcome, leakage outside registered oracle access,
  non-finite output, failed exact-budget guard, or budget exhaustion.
